# 新版 Codex 数据读取兼容（2026-10-26）

本机 Codex CLI 版本为 `0.164.0-alpha.11.1`。v2.0.2 能完成初始化，但 `account/read` 在约 15 秒后返回 `-32603: workspace routing discovery timed out`。监控程序将其记为 `ACCOUNT_ERROR` 并提前返回，未执行后续额度请求。独立调用 `account/rateLimits/read` 仍成功，返回额度窗口、重置卡数量和 `accountId`。

当前 CLI 本地生成的 `GetAccountRateLimitsResponse` JSON Schema 将 `accountId` 定义为该用量快照对应的账户标识；`GetAccountResponse` 中的邮箱允许为空，额度快照中的订阅类型也允许为空。

修复将额度请求放在前面。响应具有有效账户标识时直接解析数据，不依赖单独的资料请求；缺少标识时再调用旧版账户接口。账户标识在内存中使用区分大小写、带独立命名空间的 SHA-256 指纹；旧版邮箱指纹行为保持兼容。显式返回未登录或非订阅账户时仍拒绝复用订阅数据。查询仍共享 30 秒总时限，不增加子进程数量。

验证覆盖快照单独读取、资料路由失败、旧版回退、可空字段、显式退出登录、账户切换和卡片明细隔离。93 项核心检查通过；修复后的本机真实查询成功，包含一个额度窗口及重置卡数量。首轮服务端只返回卡片数量，后续复测返回了完整明细响应，程序兼容两类信息状态。测试报告不保存邮箱、原始账户标识或认证内容。
