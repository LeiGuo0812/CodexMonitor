# C++ 原生迁移说明

## 交付范围

原生版本为 `2.0.0-native-preview`。运行入口、额度模型、协议、进程管理、设置、任务栏数字条、详情、设置页、托盘和清理功能均由 C++ 实现。默认构建和发布入口已切换到原生目标。

原 C# 代码保留在 `src/`，用于迁移对照及回退；不参与原生构建，不会打包进原生 EXE。当前没有发布新的 GitHub Release。

### 原生模块

| 模块 | 内容 |
| --- | --- |
| `native/src/core.*` | 设置兼容、额度及卡片解析、窗口选择、账户变化隔离、日期格式 |
| `native/src/platform.*` | app-server 管道、超时、Job Object、路径发现、缓存清理、启动项、任务栏定位 |
| `native/src/render.*` | DirectWrite 格式缓存、Direct2D 绘制、透明数字条、主题 |
| `native/src/application.*` | Win32 消息、窗口、原生设置控件、菜单同步、拖动、刷新调度 |
| `native/src/main.cpp` | 入口、旧版兼容单实例锁与激活事件 |

主界面使用 DirectWrite / Direct2D；文本输入、下拉框和设置操作按钮使用原生 Win32 控件。图标和许可证在 EXE 资源内。通过 `/MT` 静态链接 MSVC 运行库，不需要随包分发 VC++ DLL。

为降低常驻资源，数字条和小型面板使用 Direct2D 软件绘制，系统磨砂仍交由 DWM 合成。不会为了这个低频更新的界面长期保留独立的应用 D3D 设备。详情、设置的绘制目标按需创建，关闭和最小化时释放；文字格式复用，文字变化才重新测量；动画只在加载与悬停过渡期间运行。

## 行为兼容

- 主额度选择不依赖 primary/secondary 的名字，按窗口时长或明确语义识别。5 小时耗尽仍显示 0%，暂缺保留可信旧数据，账号变化和退出登录时清除旧账户状态。
- 周重置和 5 小时重置各自取服务端时间，卡片到期不充当自然重置。未知时间不推算；倒计时到零只等待确认，不自行恢复额度。
- 卡片总数与明细数组独立；保留重复到期日，未知到期排在末尾。
- 数字条透明、系统文字色、彩色标签和柔光边缘保留。托盘沿用原图标。
- 数字条与图标单击／双击均打开同一详情窗口；右键菜单、拖动、三种位置模式、全屏隐藏保留。
- 详情初始宽度 380 DIP，下缘贴任务栏上缘；两种重置读条、10 DIP 进度条、人类可读日期、复制及 UTC 功能保留。没有 5 小时额度时为等宽纵向布局。
- 主题预设、显示模式、自定义颜色、浓度、字号、偏移、刷新频率、CLI 路径与设置预览保留。右键菜单和设置选择同步，取消不会撤销已通过菜单保存的选择。
- 刷新仍默认 60 秒，可设置 30–3600 秒。查询在工作线程中执行，合并重复触发，失败退避；唤醒与网络接口变化可触发刷新。

设置页的浓度、字号与偏移由 WinUI 滑块改为原生数值输入框，范围和预览功能相同。其他原生控件也不是 WinUI 的逐像素复制。

## 配置

仍使用 `%LOCALAPPDATA%\CodexQuotaMonitor\settings.json`，沿用 PascalCase 属性名、数字枚举值和默认值。无需导入／导出，原生版直接读取旧配置，保存后旧版也能识别。

仅在用户保存设置、通过菜单修改设置或拖动完成时写文件；先写临时文件，再替换正式配置。额度、账户指纹和原始接口响应不落盘。发生异常时才写同目录的 `native-failure.json`，只记录错误代码和时间。

## 缓存与清理

| 对象 | 原生版行为 |
| --- | --- |
| .NET / Windows App SDK 依赖释放 | 不再发生；没有 `%TEMP%\.net` 版本缓存 |
| 内存中的额度快照 | 仍保留以便即时打开详情；退出进程后消失 |
| 旧版依赖缓存 | 清除缓存时检查固定所有权标记和目录结构，仅删除本程序所属目录 |
| 异常诊断 | 清除缓存同时删除旧 `ui-failure.json` 与新 `native-failure.json` |
| 用户设置和启动项 | 保留 |
| Codex 登录文件、Codex 自身缓存 | 不读取、不复制、不清理 |
| Windows 字体、图标、预取等记录 | 由系统维护，不属于本程序清理范围 |

清理使用 C++ 文件接口，不再启动 PowerShell 清理助手，也没有需要等自身退出才能删除的原生运行库缓存。旧版本仍占用文件或目录无访问权限时会提示不能全部清理。

扫描根目录与旧版一致：当前用户临时目录的 `.net`，以及当前 `DOTNET_BUNDLE_EXTRACT_BASE_DIR`。此前使用但现在不再设置的自定义根目录无法自动追溯。

## 开机启动

仍是当前用户注册表项：

```text
HKCU\Software\Microsoft\Windows\CurrentVersion\Run
值名：CodexQuotaMonitor
值："原生EXE的绝对路径" --background
```

不需要管理员权限，不创建服务、计划任务或额外启动脚本。已有启动项开启时，原生版正常启动会把路径更新为当前 EXE；关闭启动项仍从右键菜单操作。移动 EXE 后运行一次即可更新已启用的路径。

原生和旧版共享单实例锁，避免同时驻留、争用配置和重复显示托盘图标。要使用原生版，需要先从旧版菜单退出。再次启动同一原生版会打开已有实例的详情。

## 本机资源观察

2026-09-27 对最终交付 EXE 的短时间观察如下。单位为 MiB（1,048,576 字节），仅统计监控主进程，不包含临时 Codex CLI 查询子进程。

| 状态 | 工作集 | 私有内存 |
| --- | ---: | ---: |
| 新启动，仅任务栏驻留，5–30 秒的六次采样 | 25.4–25.8 | 10.9–11.1 |
| 详情打开时 | 49.7 | 26.1 |
| 详情与设置均打开时 | 56.0 | 34.2 |
| 72 次主题预览、关闭窗口后的检查结束时 | 48.5 | 23.1 |
| 随后正常运行、一个内容窗口可见时的补充采样 | 64.2 | 41.8 |

窗口关闭后句柄和绘制目标已销毁，但字体、堆分配及系统组件缓存未必立即归还，因此打开过窗口后的驻留值高于新启动。不同运行阶段的数值有波动，不能把初始约 26 MiB 当作全程占用上限。以上不是长期峰值或泄漏结论，也不是旧版与新版的受控百分比对比。查询子进程仍使用现有 Codex CLI，迁移不降低该进程本身的内存需求。

交付 EXE 为 763,392 字节（约 746 KiB）；本机保留的旧 v1.0.6 单文件为 94,538,619 字节。文件缩小主要来自移除捆绑的 .NET / WinUI 运行时，不能将文件体积比例当作内存节省比例。

## 已完成的检查与边界

- C++ Release 编译和单 EXE 打包。
- 51 项原生核心检查：额度优先级、字段暂缺、账户切换、未知／零／极小值、非法值、时间边界、卡片数量与明细、重复到期、配置兼容等。
- 真实 Codex 查询成功，返回额度窗口及重置卡总数字段；当前账户接口只有卡片数量时，界面如实显示明细暂不可用。
- 本机 175% 缩放下检查数字条、详情和设置截图；修正了首次打开隐藏、重复标题栏、磨砂中 GDI 控件文字透明的问题。
- 运行检查覆盖 72 次主题切换、设置与实际 Win32 菜单状态同步、单击／双击事件处理复用详情、详情下缘与任务栏上缘间距 0、关闭窗口后销毁句柄和绘制目标。
- 检查 EXE 导入表只依赖 Windows 系统 DLL，无 .NET、WinUI、Windows App SDK 或动态 VC++ 运行库依赖。

这些检查不能替代全部人工交互验收。100%／125% 缩放、跨 DPI 拖动、Explorer 重启、自动隐藏任务栏、休眠恢复、实际系统面板遮挡和长期连续运行仍需继续检查。当前版本不宣称与 WinUI 逐像素一致。

**音量面板问题仍保留为已知限制**：任务栏可进入高于普通应用的系统显示层。此次没有提权、注入 Explorer 或强行修改系统显示层；保留用户选择的任务栏内位置，不将技术栈迁移描述成该问题的修复。

原生窗口检查通过 `--verify-native` 显式启用，使用独立诊断实例，不改写用户设置和启动项，不执行缓存删除。普通启动不会自动运行这些检查。
