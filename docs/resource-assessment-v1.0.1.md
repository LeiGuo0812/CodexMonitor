# v1.0.1 资源占用实测

## 环境与方法

- 日期：2026-09-27；Windows 11 专业版 10.0.26200，16 个逻辑处理器，175% 显示缩放。
- 正式自包含单文件 EXE；SHA-256：`bb4ccb456793762a65729d1d0b64ce937ab1d0a3204a124383c3807f99cf5835`。
- 启动预热 15 秒，后台 120 秒，详情打开 45 秒，每 3 秒触发刷新共 60 秒，关闭详情后观察 60 秒。共采集 1,090 个样本；采样目标间隔 250 毫秒，实际包含进程枚举和读取开销。
- 仅跟踪该 EXE 及其后代查询进程，不包含用户另外运行的 Codex 桌面版或采样脚本自身。观察到 50 个短生命周期后代进程，最多同时存在 2 个。
- 未调用强制 GC 或工作集裁剪；测量期间桌面其他应用仍在正常运行，结果不是隔离环境下的性能上限。

## 统计口径

- **工作集**：当前驻留物理内存，包括共享 DLL 等页面。它不是程序独占的物理内存；多个进程工作集相加可能重复计算共享页。[Microsoft 说明](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.workingset64?view=net-10.0)
- **私有提交量**：进程不能与其他进程共享的已提交内存，对应 Private Bytes；不等于当前驻留的私有工作集，也不能与工作集相加。[Microsoft 说明](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.privatememorysize64?view=net-10.0)
- CPU 按全部 16 个逻辑处理器归一化，100% 表示整机处理器容量，表中为阶段平均值。
- 峰值是采样观察值；短于采样间隔的进程或瞬时尖峰可能遗漏。未测量 GPU 显存、DWM 的间接占用或内核级归属。

## 判断

后台初始 CPU 消耗较低；主程序工作集为百 MiB 级，不能宣称“极低内存”。连续使用后内存高于首次后台状态，关闭详情也没有立即回到初始值。仅凭这轮短测无法区分框架缓存、GC 保留和泄漏，需要结合后续观察，不能宣称已证明不存在泄漏。

因此额外附加到同一进程，在关闭详情的状态下观察 120.14 秒、435 个样本。私有提交量从 **124.92 MiB 到 125.05 MiB**，尾段基本稳定，工作集平均 **214.56 MiB**；主程序与查询子进程 CPU 平均合计 **0.343%**。短期内没有持续明显增长，但使用后的驻留内存高于首次后台约 58 MiB（工作集口径）。这是需要关注的资源保留现象，尚不能凭此确定泄漏，也不能排除长时问题。

主程序句柄数在首次后台阶段为 2,010→2,018，在额外观察阶段为 2,294→2,324；这项也需要更长时间观察释放与复用，未据短测下“无泄漏”结论。

如果继续优化，优先检查重复刷新时的对象分配、窗口关闭后的原生资源释放及 Shell 事件触发频率；不应以强制清空工作集制造较低读数。当前“清除缓存”清理的是磁盘文件，不用于降低进程内存。

## 复现

```powershell
# 先退出 CodexMonitor；约 5 分钟，结束后程序继续运行
.\scripts\Measure-Resources.ps1 -ApplicationPath .\releases\v1.0.1\CodexMonitor-v1.0.1-win-x64.exe

# 附加到已运行的同一 EXE，额外观察后台；替换进程 ID
.\scripts\Measure-Resources.ps1 -ApplicationPath .\releases\v1.0.1\CodexMonitor-v1.0.1-win-x64.exe `
    -AttachProcessId 12345 -IdleOnly -IdleSeconds 120 -ReportPath .\.artifacts\extended-idle.json
```

原始采样报告写入 `.artifacts`，不进入发行包。不要把这次单机短测推广为所有硬件、缩放或使用时长的保证。
