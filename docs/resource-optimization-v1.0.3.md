# v1.0.3 按需资源更新与测量

## 实际修改

1. **系统外观**：UISettings / AccessibilitySettings 使用进程级惰性单实例，复用任务栏配色与应用主题计算结果。Windows 设置、主题、DWM 色调及时间变化消息触发失效更新；15 秒补充检查。仅缓存最新状态，没有累积历史主题。
2. **任务栏数字条**：将两个每秒定时器合为一个。每秒仍检查位置、全屏和倒计时边界，但文字未变化时复用格式化结果，不重新设置提示或测量宽高。颜色未变化不创建新画刷；全屏隐藏期间暂停文字更新。
3. **任务栏定位**：复用前台窗口类名缓冲区；枚举子窗口时使用同一个缓冲区，避免为每个子窗口重新创建。保留任务栏位置和遮挡检查。
4. **详情卡片**：按行保留控件，更新现有文字；新增行才创建，减少行即移除。相同快照的刷新忙碌状态只改变刷新按钮，主题未变化也不重新生成画刷。重复卡片 ID 或相同到期时间仍分别保留。
5. **详情时间**：按可见倒计时、日期、时区和更新时间变化更新文字。卡片有效期和其他额度倒计时也随本地时间更新。自然重置进度以 0.1 个百分点更新，低于当前卡片宽度的一个像素，不以此修改真实额度数据。
6. **窗口生命周期**：详情最小化停止 UI 时钟并推迟内容更新，恢复时显示最新快照。关闭时停止动画、解除计时器/窗口事件订阅并清空动态行。详情、设置原本即按打开需求创建，此行为继续保留。
7. **其他**：设置预览的外观相同则复用；托盘提示相同则不重复提交 Shell；协议直接解析已读取的 JSON 元素，消除二次序列化和解析；查询 stderr 使用有界缓冲区丢弃，不逐行创建字符串。

仍保留每秒的轻量时钟检查，确保重置边界、系统时钟变化、全屏退出和任务栏位置恢复及时。自动查询默认仍为 60 秒，可配置。未改为常驻 app-server，也未使用强制 GC 或工作集裁剪。

## 实测方法

- Windows 11 10.0.26200、16 个逻辑处理器、175% 缩放；同一台机器、同一设置（60 秒查询），前后分别从新进程启动。
- 前：正式 v1.0.2 EXE，SHA-256 `a25874e41eefd32dbdc7289ea23f693a9ded5bc68f6e66f20fa8be8d1957ff12`。
- 后：v1.0.3 EXE，SHA-256 `a64aa9317a13ecc1fb250836dc6350d6cde1acd4e2ef509190ce093a7adde3a6`。
- 两次都使用 `scripts/Measure-Resources.ps1`：预热 15 秒、后台 120 秒、详情 45 秒、每 3 秒触发刷新共 60 秒、关闭详情后观察 60 秒，目标采样间隔 250 ms。
- 统计主程序及其后代查询进程。CPU 按整机 16 个逻辑处理器归一化；私有提交量不是私有物理工作集。工作集包含共享页，不能将多个进程工作集之和视为独占 RAM。
- 系统上的其他应用继续运行。每版各一轮，属于实机对照观察，不能给出统计显著性、精确组件归因或长时间无泄漏结论。

## 主程序实测对照

内存单位 MiB；以下均为阶段平均值。CPU 为整机归一化百分比。

| 阶段 | 工作集：前 → 后 | 私有提交：前 → 后 | CPU：前 → 后 |
| --- | ---: | ---: | ---: |
| 预热 15 秒 | 147.20 → 138.00 | 72.24 → 66.51 | 0.366% → 0.646% |
| 后台 120 秒 | 154.65 → 150.40 | 76.87 → 73.60 | 0.041% → 0.028% |
| 详情打开 45 秒 | 170.86 → 193.42 | 93.74 → 111.92 | 0.445% → 0.269% |
| 连续刷新 60 秒 | 180.94 → 203.71 | 103.90 → 120.73 | 0.594% → 0.184% |
| 关闭详情后 60 秒 | 188.72 → 205.69 | 111.38 → 120.37 | 0.031% → 0.003% |

**不能宣称常驻内存全面下降。** 首次后台有小幅下降，但打开详情后的工作集和私有提交量在本轮较高。CPU 与分配吞吐下降，不等于总进程内存必然下降。未进行原生堆/模块分配跟踪，不能把差额准确归因于磨砂、字体缓存、代码加载或某个缓存对象。需要进一步重复测量及原生内存剖析，才能区分回归与运行波动。

预热平均值受到单文件解压时间和启动进度影响，不作为常驻改善指标。关闭详情后的新版本私有提交量在该阶段从 122.59 降至 119.98 MiB；这是本轮现象，不等于长期稳定性结论。

### 托管分配补测

两版在各自测量之后保持后台运行，分别附加 dotnet-counters 10.0.745401，采集 20 秒的 `EventCounters\System.Runtime`。旧版本在主测量结束后额外运行了更长时间，新版本较快附加，因此两段不是完全相同的运行时长。诊断附加本身也有开销；不能将这里的堆大小直接与上表进行逐项相减。

| 指标 | v1.0.2 | v1.0.3 |
| --- | ---: | ---: |
| 分配速率均值 | 60,288 B/s（58.88 KiB/s） | 15,136.8 B/s（14.78 KiB/s） |
| GC 堆近似值范围（十进制 MB） | 11.05–12.22 MB | 6.52–6.80 MB |
| 采样期各代 GC 次数 | 0 | 0 |

这两段分配速率相差约 75%，与重复分配减少的代码检查一致，但不是长期保证。堆近似值可能包含未回收对象，不是严格的存活堆统计。计数器口径与复现命令见 [前一版内存分析](memory-analysis-v1.0.2.md)。

## 行为验证

102 项核心/协议测试通过；额外检查倒计时缓存与原格式化逻辑在 0–49 小时内各边界一致、时钟回拨会更新。

单文件运行自检验证：100 次不变输入更新后标签/状态/背景画刷引用保持相同，新增文字测量和系统外观读取均为 0；同值快照/忙碌状态复用详情卡片，改变内容也复用，减少卡片立即移除；最小化停止时钟，恢复重启。真实额度读取、72 次主题/细节切换、设置标题栏、拖动、悬停、开机启动、清缓存等原检查复测通过。

首次自检在窗口位置环节读到最小化状态，资源检查本身通过；相同 EXE 复测通过。详见 [验证边界](validation.md)。

## 可继续优化的范围

当前数字条仍使用 WinUI，因此 .NET / XAML / Composition 的加载成本继续存在。此次主要降低重复分配和更新，不代表能够卸载整个界面框架。若需要进一步大幅降低首次后台常驻基线，需要另行将数字条改为原生 Win32/DirectWrite，或拆分详情进程；涉及 DPI、透明背景与交互重新验证。
